\section{Phase 2: Data Acquisition and Preprocessing}

\subsection{Collection}
Raw images were collected from two sources, giving 5,013 images across the 14 dishes before any cleaning. Kaggle contributes 1,154 of them and Bing scraping the remaining 3,859.

\paragraph{Bing image scraping.} The script \texttt{collect\_images.py} downloads images from Bing using the \texttt{icrawler} package, with five query variants per dish. Every downloaded URL is logged in \texttt{raw\_metadata.csv}, so each image can be traced back to where it came from.

\paragraph{Kaggle dataset.} The script \texttt{import\_dataset.py} imports four classes from the Kaggle ``Indian Food Classification'' dataset (Pushkar Jain) and maps them onto our dishes: \texttt{samosa} $\rightarrow$ samosa (262 images), \texttt{pakode} $\rightarrow$ pakora (278), \texttt{dal\_makhani} $\rightarrow$ daal (321) and \texttt{kaathi\_rolls} $\rightarrow$ paratha\_roll (293). The remaining ten dishes come only from Bing.

\subsection{Cleaning Implementation}
Cleaning is done by \texttt{clean\_data.py}, which never deletes the raw files: the images that pass are copied into a separate \texttt{data/clean} folder, together with \texttt{clean\_metadata.csv} and \texttt{cleaning\_report.csv}. The script applies the following checks:
\begin{itemize}
  \item \textbf{Missing labels and duplicate metadata rows:} rows with no dish label, or repeated rows, are dropped.
  \item \textbf{Missing or corrupt files:} images that are not on disk or cannot be opened are dropped.
  \item \textbf{Tiny images:} images whose shorter side is below 150 pixels are dropped.
  \item \textbf{Extreme aspect ratio:} images with an aspect ratio above 3 are dropped.
  \item \textbf{Blur:} images whose Laplacian variance is below 40 are dropped as blurry.
  \item \textbf{Exact duplicates:} images with an identical MD5 hash are dropped.
  \item \textbf{Near duplicates:} images whose perceptual hash distance to an earlier image is at most 4 are dropped.
\end{itemize}
The script also records the width, height, brightness and blur score of every kept image, which are used for the exploratory analysis. Of the 5,013 raw images, 1,124 (22.4\%) were removed and 3,889 (77.6\%) were kept. Table~\ref{tab:cleaning} shows what each step removed, as reported in \texttt{cleaning\_report.csv}; the report does not list separate counts for the missing-file, corrupt-file and tiny-image checks.

\subsection{Feature Strategy}
The script \texttt{preprocess.py} prepares the cleaned images for model training in the following way.

\paragraph{Label encoding.} The 14 dish names are sorted alphabetically and mapped to integer ids: aloo\_gosht = 0, chicken\_biryani = 1, chicken\_karahi = 2, chicken\_tikka = 3, daal = 4, haleem = 5, halwa\_puri = 6, nihari = 7, pakora = 8, palak\_paneer = 9, paratha\_roll = 10, pulao = 11, samosa = 12 and seekh\_kebab = 13. The mapping is saved in \texttt{classes.json}.

\paragraph{Resizing and scaling.} Every image is resized to $224 \times 224$ pixels, the input size of EfficientNet-B0, and its pixel values are scaled to the range $[0,1]$.

\paragraph{Stratified split.} The 3,889 cleaned images are divided 70/15/15 into training, validation and test sets. The split is stratified by dish, so each set keeps roughly the same class proportions, and it uses a fixed random seed (42) so it can be reproduced. Because duplicates were removed before splitting, near-identical images cannot end up in both the training and test sets.

\subsection{Limitations}
\begin{itemize}
  \item \textbf{Watermarks and text overlays:} images scraped from Bing can contain watermarks, captions or text overlays, which the automatic blur and duplicate filters do not remove. Stock-photo watermarks (for example Alamy and Shutterstock), text banners (some in Urdu) and even a menu flyer are visible in the sample grid. A model could pick up on these instead of the food.
  \item \textbf{Label noise:} in the random sample grid (four images per dish), a few images do not appear to show the labelled dish (for example in palak\_paneer and halwa\_puri). The cleaning filters cannot detect wrong-dish images and the dataset was reviewed only by sampling, so some mislabelled images probably remain.
  \item \textbf{Source bias:} four dishes (samosa, pakora, daal and paratha\_roll) draw on a single Kaggle dataset, while the other ten come only from Bing. The two sources may differ in photographic style, so a model could partly learn the source instead of the dish.
  \item \textbf{Close substitutes:} the Kaggle classes \texttt{dal\_makhani} and \texttt{kaathi\_rolls} stand in for daal and paratha\_roll. They are similar dishes but not identical to what the project is meant to recognise.
  \item \textbf{Class imbalance:} raw counts range from 229 to 636 images per dish and cleaned counts from 128 to 498. chicken\_karahi, with 128 images, is below the 150-image target we set, and with a 15\% split its validation and test sets contain only about 19 images each, so its results will be noisy.
  \item \textbf{Licensing:} the scraped images belong to their original owners. They were collected for academic use only and are not redistributed: the dataset is excluded from the repository.
\end{itemize}
